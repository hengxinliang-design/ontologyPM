# 投入成本与沉没成本：产品方案与本体模型

> 状态：已实施（本体 v1.3.0）· 2026-10 · 实施范围和已确认的决策见第 7 节
> 成本计量单位：**人天**（工时 ÷ 每人天小时数）。可选配置“标准人天成本”后折算为金额。

## 1. 业务事实

1. 项目代码是全生命周期的**成本归集对象**：销售机会阶段，员工就用项目代码填报售前工时；签约后继续沿用同一代码填报交付工时。
2. 商机赢单（转为合同订单）后，此前的售前投入属于这个项目“为获得合同而付出的成本”。
3. 商机丢单或放弃后，此前的投入无法通过合同收回，成为**沉没成本**。
4. 当前数据现状（预览数据）：工时涉及 56 个项目代码、10,039 小时，其中 97% 落在 CRM 中尚无记录的代码上，现有系统不展示这部分投入。

## 2. 财务概念映射

| 财务 / 管理会计概念 | 在 TSG PM 中的含义 | 计算口径（人天） |
|---|---|---|
| 成本对象（Cost Object） | 项目代码 | 所有工时按项目代码归集 |
| 合同取得成本 / 获客成本（Cost to Win） | 赢单项目在**签约日前**的投入 | Σ 工时（工作日期 < 首个合同签订日） |
| 履约成本（Cost to Fulfil） | 签约日及之后的交付投入 | Σ 工时（工作日期 ≥ 首个合同签订日） |
| 在途投入 / 风险敞口（类似在制品 WIP） | 尚未有结论的商机已投入的工时 | Σ 工时（商机状态为进行中） |
| 预期沉没成本（类比预期损失） | 在途投入中按赢率估计可能收不回的部分 | 在途投入 × (1 − 赢率)；无赢率时按历史赢单率 |
| 沉没成本（Sunk Cost） | 已确认丢单 / 放弃的商机的全部投入 | Σ 工时（商机结论为丢单或放弃） |
| 内部投入 | TSG999 等非项目代码 | 单列，不计入项目成本 |
| 未建档投入 | 工时代码在 CRM 中没有任何记录 | 单列，作为数据治理待办 |

**两点财务口径说明：**

- **会计口径与管理口径**：按《企业会计准则第 14 号——收入》，只有“增量”合同取得成本（如销售佣金）可以资本化，投标、售前人工无论成败都应当期费用化。本方案是**管理口径**：把售前投入计入项目全生命周期成本，用于评估获单效率和项目真实投入，不改变会计处理。
- **沉没成本谬误**：沉没成本只用于**事后复盘**（投标决策是否得当、哪类商机不值得投入），不应作为“已经投了这么多所以继续投”的依据。是否继续投入某个在途商机，应看**未来**还需多少投入和赢单的期望价值，即“预期沉没成本”和“风险敞口”。

## 3. 分析指标

| 指标 | 公式 | 管理问题 |
|---|---|---|
| 总投入人天 | 全部工时 / 每人天小时数 | 资源都花在哪里 |
| 投入结构 | 履约 / 获客（已转化）/ 在途 / 沉没 / 内部 / 未建档 各占比 | 有效投入率是否健康 |
| 赢单率（按数量 / 按投入加权） | 赢单数 ÷ 有结论商机数；赢单商机售前投入 ÷ 有结论商机售前投入 | 售前资源投到了对的商机上吗 |
| 平均获单成本 | 获客成本 ÷ 赢单项目数 | 签一个单平均要投入多少人天 |
| 获客成本占比 | 获客成本 ÷ 项目总投入 | 售前投入相对交付规模是否过重 |
| 沉没成本率 | 沉没成本 ÷（沉没成本 + 获客成本） | 售前投入中有多少打了水漂 |
| 售前投入产出（需金额权限） | 合同金额 ÷ 获客成本人天 | 每人天售前投入撬动多少合同额 |
| 在途投入账龄 | 按首次投入至今：0–3 / 3–6 / 6–12 / 12 个月以上 | 哪些商机拖得太久，需要做决定 |
| 停滞商机 | 进行中但超过 N 天（默认 90）没有新工时 | 是否应关闭并确认沉没 |

## 4. 本体模型调整

### 4.1 新对象类型：成本对象 `CostObject`（项目代码）

把“项目代码”提升为本体中的一等对象。它覆盖**所有**出现过的代码，包括 CRM 中尚未建档的代码和内部代码。项目（Project）仍是 CRM 视角的业务对象，二者通过项目代码 1:1 关联。

| 属性 | 类型 | 说明 |
|---|---|---|
| `code` | string | 主键，项目代码 |
| `registration` | enum | 已签约 / 商机 / 未建档 / 内部 |
| `opportunityOutcome` | enum | 进行中 / 已赢单 / 已丢单 / 已放弃 / 不适用 |
| `conversionDate` | date | 首个合同签订日（赢单日） |
| `firstWorkDate` / `lastWorkDate` | date | 首次 / 最近投入 |
| `totalPersonDays` | decimal | 总投入 |
| `presalesPersonDays` | decimal | 签约前投入（获客成本或在途投入） |
| `deliveryPersonDays` | decimal | 签约后投入（履约成本） |
| `sunkPersonDays` | decimal | 已确认沉没 |
| `atRiskPersonDays` | decimal | 在途风险敞口 |
| `expectedSunkPersonDays` | decimal | 预期沉没 |
| `presalesAgeDays` | integer | 在途投入账龄 |
| `stalled` | boolean | 是否停滞 |
| `estimatedCost` | money | 可选：总投入 × 标准人天成本（`FINANCE` 标记） |

新增关系：`CostObject → TimeEntry`（1:N）、`CostObject ↔ Project`（1:1）、`CostObject → Employee`（M:N，经由工时）。

### 4.2 现有对象的调整

- **TimeEntry**：新增派生属性 `costPhase`，取值为售前 / 交付 / 内部 / 未建档；赢单项目还会区分“已转化售前”。
- **Project**：新增 `presalesPersonDays`、`deliveryPersonDays`、`conversionDate`、`opportunityOutcome`、`costToWinShare`。
- **Opportunity**：新增 `investedPersonDays`。

### 4.3 新动作

| 动作 | 目标 | 作用 |
|---|---|---|
| `recordOpportunityOutcome` 记录商机结论 | CostObject / Project | 人工确认“已丢单 / 已放弃”，填写原因（竞争失败、客户取消、预算不足、主动放弃、其他）和日期；确认后，该代码的售前投入计为沉没成本 |
| `reopenOpportunity` 重新激活商机 | 同上 | 撤销结论（例如客户重启项目），需要填写理由，写入审计 |

**提交条件**：已签约的代码不能标记丢单；结论日期不能早于首次投入日。

### 4.4 新函数

| 函数 | 输出 |
|---|---|
| `costObjectInvestment(costObject)` | 单个代码的投入结构、阶段拆分、账龄、预期沉没 |
| `portfolioInvestmentAnalysis(period?)` | 全公司投入结构、赢单率、获客成本、沉没成本率、账龄分布、停滞商机清单 |

### 4.5 安全

- 人天类指标对拥有 `projects` 或 `resource` 权限的用户可见。
- 一旦配置了标准人天成本，折算出的金额加 `FINANCE` 标记。

## 5. 产品界面

新增菜单 **“投入成本分析”**，放在“查询与运营监控”组：

1. **指标卡**：总投入、履约成本、获客成本、在途投入、已确认沉没、预期沉没、未建档投入、沉没成本率、赢单率。
2. **投入结构**：按月份的堆叠条形图，分履约 / 获客 / 在途 / 沉没 / 内部 / 未建档。
3. **在途商机**：按风险敞口排序，显示赢率、账龄、预期沉没和停滞标记，可直接执行“记录商机结论”。
4. **沉没成本复盘**：已丢单 / 放弃商机的投入、原因分布、按客户或按负责人统计。
5. **未建档代码**：有工时但 CRM 没有记录的代码，提示补录。
6. **项目详情抽屉**：新增“投入分析”区块，显示售前与交付拆分和签约日。

## 6. 数据规则与边界

- **签约日**：同一代码有多份合同（例如追加合同）时，取最早的合同签订日。
- **商机结论来源**：优先采用人工“记录商机结论”；其次采用 CRM 中表示失败的状态值（映射可配置，例如“失败 / 丢单 / 关闭”）。CRM 状态为“成功”或已有合同时，视为赢单。
- **停滞判定**：默认 90 天无新工时，阈值可配置。系统只把这类商机标为“疑似停滞”，不会自动确认沉没。
- **签约后又出现丢单状态**：以合同为准，不计入沉没。
- **内部代码**：内部代码清单可配置，默认 TSG999。

## 7. 已确认决策与实施状态

### 7.1 已确认的三项决策

| 问题 | 决策 | 实现 |
|---|---|---|
| 沉没如何判定 | 人工确认 + CRM 状态 | 结论优先级：内部代码 → 有合同即赢单 → 人工结论（`opportunity_outcomes`）→ CRM 商机“成功” → CRM 失败状态（`lost_statuses` 可配置）→ 其他商机为进行中 → CRM 无记录为未建档 |
| 是否折算金额 | 先只用人天，预留单价配置 | `investment_settings.standard_person_day_cost` 为空时只显示人天；配置后才出现金额列，金额带 `FINANCE` 标记，修改单价也需要金额权限 |
| CRM 无记录的代码 | 单列为“未建档投入” | 不计入获客或沉没，在页面单独列出，可以直接在列表里记录结论 |

### 7.2 已实现

- **后端**：`app/investment.py`（`InvestmentService`：结论登记/撤销、设置、成本对象、组合分析）；新表 `opportunity_outcomes`、`investment_settings`；接口 `GET /api/v1/investment/analysis`、`GET /api/v1/investment/cost-objects/{code}`、`GET|PATCH /api/v1/investment/settings`；菜单权限 `investment`。
- **本体 v1.3.0**：
  - 新对象类型 `CostObject`，属性见 `metadata/object-types/cost-object.yaml`；
  - 新关系 `CostObject ↔ Project`、`CostObject → TimeEntry`、`CostObject ↔ Employee`；
  - 新值类型 `CodeRegistration`、`OpportunityOutcome`、`CostPhase`、`OutcomeReason`；
  - `TimeEntry.costPhase`；
  - `Project` 新增签约日、商机结论及获客、履约、在途、沉没人天；
  - 动作 `recordOpportunityOutcome`、`reopenOpportunity`（含提交条件和审计）；
  - 函数 `costObjectInvestment`、`portfolioInvestmentAnalysis`。
- **前端**：菜单“投入成本分析”。页面包含：
  - 期间选择和设置（单价、停滞天数、失败状态、内部代码）；
  - 8 个指标卡；
  - 投入结构条和图例表；
  - 按月堆叠图；
  - 在途商机：账龄分布，可直接记录结论；
  - 沉没成本复盘：原因分布，可重新激活；
  - 赢单项目获客成本；
  - 未建档代码。

  本体浏览器的函数结果有对应的可读视图。

**沉没成本率口径**：沉没 ÷（沉没 + 获客成本），即有结论的售前投入中收不回的部分。有效投入率 =（履约 + 获客成本）÷ 总投入。
